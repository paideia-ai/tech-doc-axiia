Edge 2: COMPUTE — ScorePool → Curve

Transformation Compute grade boundaries from the pool's distribution

What happens: For each score category (per-problem task_score, per-dimension ability, and overall), compute the mean (μ) and standard deviation (σ) across all students, then set grade boundaries:

A threshold = μ + 1σ
B threshold = μ + 0σ = μ
C threshold = μ − 1σ
D = anything below C threshold
✓ Success
⚠ Advisory

Problem 000340 task_score across 120 students

μ = 0.72, σ = 0.13

GradeConditionThresholdZone Color
Ascore ≥ μ + σ≥ 0.85
Bμ ≤ score < μ + σ≥ 0.72
Cμ − σ ≤ score < μ≥ 0.59
Dscore < μ − σ< 0.59

Student-0042's task_score of 0.80 for problem 000340 falls in the B zone (≥ 0.72 but < 0.85).

Advisory: Small sample size

Computation itself always succeeds once you have a valid pool. However:

⚠ sample_size = 15 < 30 — standard deviation may not be statistically meaningful

With only 15 students, the σ may be unreliable. The curve will still be computed, but the advisory check will flag this when the curve is applied to a student's scores.

Edge 3: CHECK — Curve + JSONScores → CompatibilityResult

Transformation Three-tier compatibility check before applying curve

What happens: Before applying a curve to a student's scores, verify compatibility. Three tiers of checks determine whether the curve can be applied automatically, needs human approval, or is blocked entirely.

Three Possible Outcomes

Compatible

All checks pass. Curve applied automatically.

Requires Override

Structural OK, provenance mismatch. Human must approve.

Incompatible

Structural fail. Blocked — cannot proceed.

Structural Checks MUST PASS

If any structural check fails, the curve literally cannot be applied to these scores.

CheckWhat it verifies✓ Success (fixture)✗ Failure (fixture)
Problem coverage Curve has boundaries for every problem the student took Curve has 000340, 000500, 001001. Student has exactly those 3. Curve only has 000340 + 000500 (missing 001001). Student has 001001 but no boundary exists for it → cannot grade.
Dimension match For each problem, curve and scores agree on which dimensions are tested Curve says 000340 tests [Discovery, Expression, Exploratory]. Scores agree — those 3 are non-null, the other 2 are null. Curve says 000340 tests [Discovery, Expression] but scores say [Discovery, Expression, Exploratory] → mismatch.
Threshold ordering A ≥ B ≥ C (thresholds are monotonically non-increasing) A=0.85 ≥ B=0.72 ≥ C=0.55 ✓ A=0.55, B=0.72, C=0.85 — inverted, indicates data corruption.

Provenance Checks SHOULD MATCH

If any provenance check fails, a human must review and explicitly approve ("override") before the curve is applied.

CheckWhat it verifies✓ Success (fixture)✗ Failure (fixture)
Prompt version Student and curve were scored with the same prompts Both have set_hash = "aabbcc…aabb" Curve: set_hash = "ffffff…ffff". Specific diff: framework:zh:task-eval: sha256 differs
Event membership Student's event is in the curve's source_event_ids Student event = "spring-2024-final", curve source = ["spring-2024-final"] ✓ Student event = "spring-2024-final", curve source = ["different-event"]
Dimension map ID Same version of the problem-dimension mapping Both map_id = "d4e5f6a7-…" Curve map_id = "00000000-…" (different version of the map)

Advisory Checks INFORMATIONAL

These never block application. They provide useful context for interpretation.

CheckWhat it checksExample
Extra curve problems Curve covers problems the student didn't take Curve has 5 problems, student only took 3 — harmless, unused boundaries are ignored.
Sample size Pool had enough students for reliable statistics 15 students < 30 threshold → ⚠ warning
Staleness Time gap between curve computation and scoring > 90 days apart → ⚠ warning
Score range Are scores within the curve's practical grading range Some scores below all C thresholds → many D grades, flagged for review.

Summary

The pipeline transforms raw LLM scores into letter grades through 4 steps:

StepInputOutputCan fail?
1. COLLECT JSONScores (×N) ScorePool Yes — prompt/dimmap mismatch rejects students
2. COMPUTE ScorePool Curve No (advisory: small sample)
3. CHECK Curve + JSONScores CompatibilityResult Yes — 3 tiers: structural/provenance/advisory
4. APPLY Curve + JSONScores CurvedScores Yes — blocked if incompatible
